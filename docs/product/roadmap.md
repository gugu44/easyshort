# EasyShort 제품 로드맵

## 1. 제품 목표

EasyShort는 개인 사용자가 웹에서 빠르게 숏폼 영상을 만들 수 있게 하는 B2C 제작 도구입니다. 사용자는 이메일 로그인 후 개인 워크스페이스에서 사진, 영상, 대본을 업로드하거나 AI로 대본을 생성한 뒤 음성, 자막, 화면비, 전환 효과를 조합해 9:16 숏폼 영상을 만들 수 있습니다.

## 2. B2C 제품 원칙

- 모든 사용자는 Supabase Auth의 `auth.users.id`를 기준으로 개인 워크스페이스를 갖습니다.
- 프로젝트, 업로드 에셋, 대본, 자막, 렌더링 job, 결과 파일은 반드시 `user_id`로 소유자를 기록합니다.
- 대시보드와 API는 로그인한 사용자의 데이터만 조회/수정/삭제할 수 있습니다.
- 무료 플랜은 월간 생성 횟수, 렌더 크레딧, 저장소 사용량 제한을 제공하고 이후 유료 플랜으로 확장합니다.
- 개인정보와 사용자 API Key는 서버 측 암호화 및 RLS 정책을 전제로 저장합니다.

## 3. 핵심 기능 범위

### 3.1 1차 MVP: 사진 → 숏폼

가장 먼저 구현할 기능은 사진 여러 장과 대본을 기반으로 숏폼을 생성하는 흐름입니다.

- 사진 3~10장 업로드
- 사진 순서 변경
- 직접 대본 작성
- AI 대본 생성 옵션
- 무료 음성 테스트 또는 Typecast 연동 준비
- 자막 스타일 선택
- 9:16 미리보기
- MP4 다운로드

### 3.2 2차: 일반 영상 → 숏폼

- 영상 업로드
- 시작/끝 구간 선택
- 9:16 크롭 영역 지정
- 자막 추가
- 음성 교체 또는 유지
- 렌더링/다운로드

### 3.3 3차: STT 기반 자동 자막

- 영상 오디오 추출
- STT provider 호출
- transcript 저장
- SRT/VTT 생성
- 자막 편집 UI 제공

### 3.4 4차: 롱폼 → 하이라이트 숏폼

- 롱폼 영상 업로드
- STT transcript 생성
- AI 하이라이트 후보 분석
- 후보 구간 선택
- 숏폼 편집/렌더링

### 3.5 5차: 기존 숏폼 재가공

- 기존 숏폼 업로드
- 대본/자막 추출
- 후킹 문구 재생성
- 자막 스타일 변경
- 음성 교체
- 새 버전 렌더링

## 4. 단계별 구축 계획

### Phase 0. 기획 확정

- MVP 입력 타입 확정
- 무료 테스트 범위 확정
- 렌더링 방식을 브라우저 우선으로 시작할지 결정
- Typecast를 필수 기능이 아닌 선택 provider로 설계

### Phase 1. B2C 사용자 기반 구축

- React + Vite 프로젝트 생성
- Cloudflare Pages 배포 설정
- Supabase 프로젝트 연결
- Supabase Auth 이메일 매직링크 로그인 연결
- 보호 라우팅과 로그인 페이지 구성
- 사용자별 대시보드와 프로젝트 생성 화면 구현
- 무료 플랜 사용량 카드와 저장소 사용량 표시

### Phase 2. 파일 업로드와 프로젝트 관리

- Supabase Storage 버킷 생성
- `projects` 테이블 생성 및 `user_id` 소유자 컬럼 추가
- `assets` 테이블 생성 및 `user_id`, `project_id` 범위 검증
- 사진/영상 업로드 진행률 표시
- 프로젝트 목록/상세 조회 구현

### Phase 3. 사진 → 숏폼 MVP 구현

- 사진 업로드 wizard 구현
- 사진 순서 변경
- 직접 대본 입력
- 자막 문장 분리
- 자막 스타일 선택
- 음성 provider 선택
- 9:16 미리보기
- 브라우저 기반 렌더링 또는 렌더링 job 생성

### Phase 4. AI 대본 생성

- LLM provider adapter 설계
- 무료/유료 provider 설정 UI 구현
- 주제, 톤, 길이, 타깃 기반 대본 생성
- 생성 결과 수정 UI 구현

### Phase 5. 음성/TTS 연동

- TTS provider adapter 설계
- 무료 브라우저 TTS 또는 mock TTS 제공
- Typecast API Key 저장 화면 제공
- 음성 미리듣기와 생성 결과 저장

### Phase 6. 자막 시스템

- subtitle segments 데이터 구조 확정
- 자막 스타일 preset 구현
- SRT/VTT 내보내기
- 영상 burn-in 렌더링 지원

### Phase 7. 영상 기반 기능 확장

- 일반 영상 구간 선택
- 세로 크롭 지정
- STT 자동 자막
- 롱폼 하이라이트 후보 추천
- 기존 숏폼 재가공

## 5. 우선순위 원칙

1. 영상 자동 분석보다 사진 기반 MVP를 먼저 완성합니다.
2. Typecast 같은 유료 API는 교체 가능한 provider로 설계합니다.
3. 무료 테스트를 위해 mock/free provider를 항상 제공합니다.
4. 장시간 영상 처리 작업은 동기 API가 아닌 job 기반으로 분리합니다.
5. 사용자 API Key는 프론트엔드에 노출하지 않습니다.
6. 모든 신규 기능은 로그인 사용자 기준의 RLS, quota, billing 영향을 먼저 검토합니다.
